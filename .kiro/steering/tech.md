# Technology

## Stack

- **Infrastructure:** AWS CDK v2 in TypeScript (`infra/`), using Node.js 20+ and npm.
- **Runtime integration:** Python for AgentCore gateway Lambdas, metering functions, the Claude pipe/seeder, and capability probing.
- **Console:** React, TypeScript, Vite, and Cloudscape for the optional metering administration and self-service UI.
- **Deployment:** Bash `deploy.sh` orchestrates AWS account/region selection, CDK bootstrap/deploy, dependency vendoring, stack-output collection, and ECS environment updates.
- **AWS services:** ECS Fargate, CloudFront, internal ALB, VPC, Aurora PostgreSQL with pgvector, ElastiCache Redis, S3, DynamoDB, EventBridge, SQS, Secrets Manager, Cognito, Lambda, Bedrock, and Bedrock AgentCore.
- **Application:** Official Open WebUI container, operator-selectable via `OPEN_WEBUI_IMAGE` in `.env` (default: latest official release) and resolved to an immutable digest at deploy time by `scripts/resolve-owui-image.py`; there is no Docker build in this repository.

## Code conventions

- Keep CDK resources grouped by domain stack and pass cross-stack resources through typed stack props; declare explicit stack dependencies in `infra/bin/app.ts`.
- Follow the existing TypeScript style: 2-space indentation, single quotes, semicolons, and explicit interfaces/types where useful.
- Follow established Python module style and keep Lambda handlers/runtime integrations small and AWS-service focused.
- Keep behavior driven by configuration where it already is; do not hard-code model capability or pricing lists into interceptors or pipes.
- Preserve MIT-0 copyright/SPDX headers on authored source files.

## Configuration

- Root `.env` is deployment/application state and must not be committed. Start from `.env.example`.
- CDK configuration precedence is CLI context, then `infra/deploy.config.json`, then code defaults/environment presets.
- `infra/deploy.config.json` and `infra/cdk.context.json` are generated local deployment state.
- `config/model-capabilities.json` is generated by `scripts/probe-model-capabilities.py`; prefer regeneration over manual edits.
- Deploy-time Python dependencies under gateway and metering function directories are vendored by `deploy.sh` and are gitignored.

## Common commands

Run deployment commands from the repository root in a Bash-compatible shell:

```bash
cp .env.example .env
./deploy.sh
./deploy.sh --env-only
./deploy.sh --skip-bootstrap
```

Run metering tests from the repository root:

```bash
python -m pytest metering/tests -q
```

Run infrastructure checks from `infra/`:

```bash
npm install
npm run build
npx tsc --noEmit
npx cdk synth --quiet
npx cdk diff
```

Build the optional console from `console/`:

```bash
npm install
npm run build
```

`npm run watch` starts the TypeScript compiler in watch mode and should only be run interactively. Use the metering pytest suite, TypeScript compilation, console build, and CDK synthesis as the baseline validation appropriate to the files changed.
