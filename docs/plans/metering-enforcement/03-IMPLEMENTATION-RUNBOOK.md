# 03 — Implementation Runbook (phased; for a separate, authorized build run)

This is a **plan, not executed work**. Each phase is independently shippable, has a
verification gate a build run must pass before the next phase starts, and names the
files it creates and the AWS resources it deploys. The build run should execute phases
in order and stop at any failed gate. Architecture and rationale:
[`02-DESIGN.md`](02-DESIGN.md). Prerequisite: operator sign-off on the design
(§7 of the design doc), including the in-repo-module decision this runbook assumes.

Conventions: all new code MIT-0 + SPDX headers; no real account IDs in committed files;
every phase ends with `npm run build && npx cdk synth` green and, where the phase touches
the off-state, the **lean-core gate** (Phase 0's `cdk diff` bit-identity check) re-run.

---

## Phase 0 — Scaffolding + the lean-core gate

**Goal:** the opt-in module exists, defaults off, and provably changes nothing when off.

Deliverables:
- `infra/lib/metering-stack.ts` — empty-shell stack behind context flag
  `metering` (`off` default; `deploy.sh --metering` convenience flag).
- `infra/bin/app.ts` — conditional instantiation (`OpenWebUI-Metering` stack), wired
  after Gateway, before Compute (Compute consumes optional filter-asset props).
- `docs/METERING.md` — operator-facing doc stub (enable/disable, cost note).

AWS resources: none while off; empty stack while on.

**Gate G0 (lean-core):** with `metering=off`, `npx cdk synth` output for all five
existing stacks is **byte-identical** to the pre-branch baseline (`diff -r cdk.out
cdk.out.baseline` empty, modulo asset-hash-invariant fields); `deploy.sh` without the
flag never mentions metering. Record the diff transcript in the PR.

## Phase 1 — Metering data plane (capture → ledger), no enforcement

**Goal:** every chat turn lands in a queryable ledger with per-user attribution.
Nothing can block a request yet.

Deliverables:
- `pipe/metering_filter.py` — global filter function (priority ≥ existing filters):
  `outlet()` extracts `messages[].usage` + `__user__` + model + ids → `PutEvents` to the
  metering bus (batched, non-blocking, swallow-all-errors so chat can never break —
  filter failure observable via its own log line + a `Metering/CaptureFailures` metric;
  PutEvents partial failures retried once then counted, never raised).
- `pipe/seed.py` — extend to upsert the filter row when `METERING_ENABLED=true` env is
  present (set by compute stack when the flag is on). Off ⇒ seeder behavior unchanged
  (G0 re-run).
- `infra/lib/metering-stack.ts` — EventBridge bus `metering`, DynamoDB tables
  `usage_ledger` (pk/sk per design §4.3, TTL), `usage_counter`, `metering_policy`
  (on-demand billing), debit Lambda (bus rule → idempotency key = provider response id,
  fallback `(chat_id, message_id)` → `TransactWriteItems{Put ledger IF
  attribute_not_exists, Update counter}` → threshold check → SNS), SNS topic
  `metering-alerts`, DLQ on the rule + Lambda (alarmed; redrive procedure documented in
  `docs/METERING.md`).
- `infra/lib/compute-stack.ts` — when on: filter asset download in the existing
  `pipeBootstrap` (same S3-asset pattern as the pipe today) + `METERING_ENABLED` env.
- Price map v1: `config/model-prices.json` generated by
  `scripts/generate-price-map.py` (AWS Price List API `GetProducts`,
  `ServiceCode=AmazonBedrock`, filter `usagetype~mantle`), keyed (region, model,
  direction, **tier**) with `effective_date` + `source`; debit Lambda loads it from the
  stack (env or S3 asset). **Unpriced model = blocking onboarding state** (design M3):
  excluded from quota-governed lanes until an operator enters a rate; `UnpricedModel`
  metric + alarm. Phase-1 sub-task: run the Claude/GPT-5 billing probe (one billed
  mantle call each → re-query CE + offer file at T+24–48 h; also check
  Anthropic-legal-entity line items) and record where the headline models actually
  bill — this decides their operator-entered rates.

AWS resources (on): 1 bus, 3 tables, 1–2 Lambdas, 1 topic, 2 DLQs, alarms.

**Gate G1:** deploy to a scratch account with `metering=on`; run one streamed chat per
lane (gw / gwr / pipe); assert (a) three ledger rows with correct user sub, model, and
token counts matching the UI's displayed usage, (b) counter incremented once per message
(re-emit the same event manually → no double debit), (c) filter deliberately broken
(bad env) ⇒ chat still streams fine, error metric fires. Tear scratch down.

## Phase 2 — Enforcement plane (interceptor v2)

**Goal:** hard quota actually blocks, on all lanes, for all clients; fail-open wrapper +
canary prove both directions.

Deliverables:
- `gateway/interceptor/index.py` — v2, superset of today's capability filter:
  JWKS-verified JWT decode (cached keys, refresh-on-unknown-`kid`), quota + RPM
  `GetItem` (+ policy cache 60 s w/ jitter), hard-limit or RPM-exhausted ⇒ 429
  short-circuit (OpenAI error body per design §4.2/§4.4, `Retry-After` on RPM), else
  body rewrite (inject `stream_options.include_usage` on `/chat/completions`; clamp
  max-tokens **per lane** — `max_tokens` on chat/messages, `max_output_tokens` on
  responses; unrecognized paths/fields pass through untouched, never inject) +
  estimate floor-debit write (idempotency = hash(sub, body-hash, minute)), structured
  per-deny decision log, grace-budgeted catch-all fail-open (`DegradedChecks` metric)
  + bare outermost handler returning an opaque body. Keep module import-light
  (boto3 only) for cold-start.
- `infra/lib/gateway-stack.ts` — when metering on: interceptor published as a **Lambda
  version behind an alias with CodeDeploy canary traffic-shifting** (10%/5 min,
  auto-rollback on error-rate/`DegradedChecks` alarms); gateway points at the alias.
  Env: table names, JWKS URL, mode `ENFORCE|OBSERVE`, clamp + grace defaults. IAM:
  DDB `GetItem` on `POLICY#*` + leading-key-scoped est-writes on `USE#`/`RPM#`, CW
  metrics — no broad grants (design §4.3 IAM boundaries). Off ⇒ today's `ModelsFilter`
  untouched (G0 re-run).
- Debit Lambda settle = `TransactWriteItems{Put ledger IF attribute_not_exists, Update
  user counter}`; group rollups via DynamoDB Streams (NOT in the transaction); sweeper
  Lambda (15-min unsettled-estimate auto-refund, refund volume metric).
- Canaries, both directions: (1) **block canary** — synthetic Cognito user with a
  1-unit hard quota, hourly gateway call, expected 429, anything else ⇒ alarm;
  (2) **capture canary** — second synthetic user with ample quota whose hourly call
  must produce a settled ledger row within N minutes ⇒ alarm on absence; plus an alarm
  on debit-events/min ÷ gateway `InboundAuthorizationSuccess` ratio (silent capture
  regression). Canary traffic uses a cheap dedicated model + is excluded from rollups
  by sub.
- `scripts/set-quota.sh` — thin CLI over the tables until Phase 4's API (put policy,
  get usage, reset counter) for operators without the console.

AWS resources (on): interceptor Lambda v2 (replaces v1's role in the gateway config),
canary Lambda + schedule + test user, alarms (`DegradedChecks`, canary, interceptor
errors, p99 duration).

**Gate G2:** in scratch: (a) user under quota chats normally on all three lanes, TTFB
delta vs Phase-1 baseline ≤ 15 ms p50 (spike says ~0–5 ms expected); (b) set 1-token
quota → next call 429s on every lane and **the quota message renders in the Open WebUI
chat window** (screenshot); (c) `GET /v1/models` still 200 while blocked; (d) direct
`curl` to the gateway with the blocked user's token also 429s AND direct-caller
estimate debits appear in the counter (the bypass-surface check, both halves); (e) kill
the DDB table name (env typo) → chat still works, `DegradedChecks` fires, grace budget
counts down (fail-open bounded); (f) canary alarm fires when the canary user's quota is
removed; (g) **burst/load probe before ENFORCE**: drive ≥ 3× expected peak RPS at the
interceptor — zero throttles at provisioned concurrency, and a forced-throttle probe
records how the gateway surfaces Lambda throttling (fail-closed characterization);
(h) deploy a no-op interceptor change through the alias/canary pipeline and observe
shift + auto-rollback on a seeded failure; (i) gateway repoint to `ModelsFilter` and
back, measuring propagation latency (the last-resort rollback, now quantified);
(j) sweeper refunds an orphaned estimate (kill a stream client-side, wait 15 min,
counter returns to baseline); (k) DLQ redrive replays a batch with zero double-debits.
Deploy mode `OBSERVE` first (log-only decisions), flip to `ENFORCE` inside the same
gate after (a)–(c) pass in OBSERVE.

## Phase 3 — Soft tier + AWS-native attribution (Projects)

**Goal:** warn-before-block UX; per-team dollars visible in Cost Explorer.

Deliverables:
- `pipe/metering_filter.py` — `inlet()` reads a compact quota snapshot (from a
  filter-valve-configured URL to the admin API's cached `GET /usage/me`, or a direct
  DDB read via task role — build-run decides; must be non-blocking with ~200 ms budget
  and fail-silent): ≥ soft ⇒ `notification` toast event (renders at v0.10.2, verified).
  **Warn-only — the inlet never raises**; the gateway 429 is the sole block (a raise
  from a stale snapshot would outlive operator resets — design §4.2 E3).
- Projects provisioning in `metering-stack.ts` (custom resource, same pattern as the
  gateway target provisioner): one Bedrock project per configured group/cost-center
  (`config/metering-groups.json`), tags (`CostCenter`, `App`) applied; interceptor v2
  injects `OpenAI-Project` / `anthropic-workspace-id` per path from its group→project
  map (env). Unmapped users ⇒ a catch-all `metering-unassigned` project (never the
  account default, so sample traffic is always distinguishable).
- `docs/METERING.md` — cost-allocation-tag activation runbook (Billing console step,
  ≤24 h lag, not retroactive) + QuickSight/CE how-to for per-team views.

**Gate G3:** scratch: soft-warn toast appears at threshold; CW `AWS/BedrockMantle`
shows the per-group `Project` dimension for gateway traffic within the metrics lag
window `[expect ≤ a few hours; exact SLA unverified — record what is observed]`;
after tag activation + 24–48 h, CE shows spend under the project tag (this sub-check is
allowed to trail the phase). Messages lane carries the workspace header (probe).

## Phase 4 — Operator surface + reconciliation

**Goal:** operators set/see/get-alerted without touching AWS consoles; finance gets a
drift-checked number.

Deliverables:
- `infra/lib/metering-stack.ts` — HTTP API (API GW) + admin Lambda: `GET/PUT
  /policy/{scope}`, `GET /usage/{subject}?window=`, `GET /usage/me`, `POST /override`,
  `POST /counter-reset` (all writes audited as ledger rows `source: ADMIN`); Cognito
  JWT authorizer restricted to the admin group; per-route throttling.
- Reconciliation Lambda (nightly, ~T+26 h): Σ **settled** ledger rows by
  (model, tier, day) vs CE `GetCostAndUsage` by mantle usage type (×1000 = tokens) —
  query scope includes Anthropic-legal-entity line items, and groups by project tag
  once tags verify. Emits `Metering/ReconciliationDriftPct` + absolute-$ metrics with
  the design's threshold scheme (page >5% or >$X, ticket >2% ×3 days, 100K-token/day
  floor), *after* subtracting the known unsettled-estimate baseline (aborts/internal
  calls) so the alarm watches regressions, not the calibrated constant; report object
  to the ops bucket. Companion job: offer-file diff → new price-map version →
  **re-rate ledger rows in the [effectiveDate, detection] window** + counter
  adjustment note (backdated-reprice handling, design M3).
- CloudWatch dashboard: spend rate, top-10 groups (from aggregate metrics), degraded
  checks, canary, drift, interceptor p99, DLQ depth.
- `scripts/generate-price-map.py` on a monthly schedule (or documented manual step) +
  `PriceMapStale` alarm (effective_date > 45 days).
- **Scheduled capability re-probe** (`scripts/probe-model-capabilities.py`, weekly —
  drift observed within 5 days [S9]): asserts lane membership AND the per-model usage
  tail (track-D close-item), writes `model-capabilities.json` + a staleness alarm;
  interceptor consumes the refreshed matrix on next deploy or via env refresh.

**Gate G4:** policy set via API reflects in enforcement within 60 s (cache TTL); usage
query matches ledger; drift metric computes against a real CE day within tolerance on
scratch traffic; dashboard renders; negative auth test (non-admin token ⇒ 403).

## Phase 5 — Hardening + publishable docs

**Goal:** production posture + the sample tells the story.

Deliverables: load test (interceptor at 100 RPS burst: cold-start rate, p99, DDB
throttle behavior ⇒ tune memory/reserved concurrency); chaos drills scripted (DDB
offline, debit backlog, filter removed) with expected-signal table in `docs/METERING.md`;
strict-mode valve (fail-closed) documented + tested; optional reservation mode
(reserve-then-reconcile) — **build only if the operator's overage tolerance demands
it** (design §4.2); README one-paragraph module mention; `docs/COST_ANALYSIS_20K_USERS.md`
§4/§5 updated to point at the real mechanism (removing the "not included" scope
apology); CHANGELOG.

**Gate G5:** full G0 re-run (off-state bit-identity); a fresh
`deploy.sh --metering` cold deploy on a clean account passes G1–G4 checks end-to-end;
docs review; **re-check the AWS surface** before merge: gateway "token limit
policies" / usage plans in the control-plane model, IAM-principal mantle attribution
("coming soon" in docs 2026-07-14), `AWS/BedrockMantle` model coverage — if any shipped,
file follow-ups to replace the corresponding custom layer.

## Cross-phase notes for the build run

- **Order matters:** metering before enforcement (never block on numbers you can't see);
  OBSERVE before ENFORCE within Phase 2.
- **Everything lands behind the flag.** Any file the off-state can reach must be
  byte-identical when off (G0 re-run at every phase).
- **Scratch-account discipline:** G1–G4 run in a disposable account/region, torn down
  per phase (the sample's existing deploy-verify CodeBuild lane fits this).
- **No new dependencies in the hot path:** interceptor stays stdlib+boto3; JWT verify
  implemented against JWKS with `python-jose`-free primitives or a vendored minimal
  verifier (build-run decision; document the choice).
- **Rollback story per phase:** P1 = remove filter row + disable rule; P2 = point
  gateway interceptor back to `ModelsFilter` (single property); P3 = stop header
  injection (env flag); P4 = API is additive; each documented in `docs/METERING.md`.
